# metatool 在线 RL

输入上下文 (x) 保留原始消息和工具描述。一条主训练轨迹是当前策略采样的完整 assistant token 序列，包括实际 EOS；状态为 (s_t=(x,y_{<t}))。本实现使用保存的工具调用目标计算反馈，不在线执行外部真实 API。

每步选择 96 个训练问题，每题采样四条完成，形成 384 条主轨迹。组内相对优势用于 PPO 更新。模型在六个 rank 上同步训练，每步每 rank 两次 optimizer 更新，共 100 步。源训练逻辑、随机种子、token 预算、采样和数据均保持不变；初始化由 `--model` 决定。

`token_weighting.py` 使用实际生成 IDs 与 byte offsets 对结构、调用 name/parameters 和 EOS 分配信用。`action_credit.py` 在可判定的错误 Call/Respond 动作标签位置减去 0.05 优势；不能将结构代理反馈当成 Respond 的语义正确性。

对合格的 Call 思考轨迹，在原生开标签之后固定 64 个词法 token 处选择中间状态，每步最多 12 个状态。分别做 STOP 与 CONTINUE 干预，各采样两次。STOP 强制原生闭标签；CONTINUE 从词法支持集中采样首 token 后继续生成。不存在合格状态时使用零梯度占位，不生成虚构输出。

每个分支的两次精确 Call 成功数为 (s_b)，比较量为 (q_b=(1+s_b)/4)。首先选择成功率更高的一侧，监督权重为成功率差的绝对值。仅当两边均两次成功、且平均增量成本相差至少 32 token 时，使用成本打破平局，权重为 0.1。其他平局权重为零。成本不重复计算公共前缀。

路线概率比较闭标签 logit 与词法 token 的 log-sum-exp；路线交叉熵系数为 0.01。辅助输出不加入主 PPO 轨迹。路线损失与主策略损失在同一 optimizer 更新前累积。

主策略损失使用 token-mean-weighted 聚合，有效 token 权重之和是分母。原 CUDA 同步边界、编译异常记录和完整恢复实现均保留。训练中的第0/50/100步验证仍启用。

监控和事后复核保留主输出、辅助输出、逐rank计数及恢复日志。日志不会成为额外模型训练反馈。这个包没有新的结果表；改变初始模型后须运行评测，不能推断性能。
